# BelfProctor — Отчёт о состоянии проекта

> Дата отчёта: 2026-06-15

---

## 1. Что такое BelfProctor

Система мониторинга рабочих компьютеров сотрудников. Состоит из трёх частей:

| Компонент | Технология | Назначение |
|-----------|-----------|------------|
| **Клиент (агент)** | C# / .NET 8, Windows Service | Устанавливается на ПК сотрудника, собирает данные |
| **Бэкенд** | Node.js / Express / PostgreSQL | Принимает данные, хранит, предоставляет API |
| **Веб-интерфейс** | React 19 / Ant Design | Панель администратора для просмотра данных |

## 2. Что сделано и работает

### Клиент (агент на ПК сотрудника)

- ✅ **Скриншоты** — захват экрана каждые 5 минут (мульти-монитор, настраиваемое качество JPEG)
- ✅ **Активность** — определение активен/неактивен пользователь через Win32 API (`GetLastInputInfo`)
- ✅ **Мониторинг процессов** — фиксация запуска/завершения программ через WMI
- ✅ **Мониторинг USB** — обнаружение подключения/отключения флешек, получение списка файлов на накопителе
- ✅ **Мониторинг сети** — отслеживание активных TCP-соединений
- ✅ **История браузера** — Chrome, Firefox, Edge (парсинг SQLite-баз, инкрементальная синхронизация)
- ✅ **Трекинг рабочих сессий** — какой файл/проект/приложение открыт, сколько времени в фокусе
- ✅ **Трансляция экрана в реальном времени** — WebSocket стриминг для онлайн-просмотра
- ✅ **Шифрование** — весь трафик клиент→сервер зашифрован AES-256-CBC
- ✅ **Очередь при отсутствии соединения** — данные копятся локально, отправляются при восстановлении связи
- ✅ **Удалённые команды** — сервер может изменить настройки клиента, скачать файлы с ПК
- ✅ **Политики безопасности** — блокировка процессов, ограничения USB
- ✅ **Автообновление** — клиент умеет скачать и установить новую версию себя
- ✅ **Установка/удаление** как Windows Service (автозапуск, PowerShell-скрипты)

### Бэкенд (сервер)

- ✅ Приём и расшифровка всех типов данных от клиентов
- ✅ Авторизация администратора (JWT + bcrypt)
- ✅ Автоматическая регистрация новых клиентов
- ✅ Heartbeat — определение онлайн/офлайн статуса агентов
- ✅ Детектор пропусков heartbeat — автоматически закрывает незавершённые сессии
- ✅ Расчёт табеля (TimesheetDay) — суммирование активного времени по дням
- ✅ Удержание данных (retention) — автоочистка старых записей
- ✅ WebSocket для команд (двусторонняя связь сервер ↔ клиент)
- ✅ WebSocket для стриминга экрана
- ✅ Разрешение проектов — сопоставление путей к файлам с названиями проектов
- ✅ Docker Compose развёртывание (PostgreSQL + бэкенд + фронтенд)

### Веб-интерфейс администратора

- ✅ **Список сотрудников** — онлайн/офлайн статус, последняя активность, быстрый доступ
- ✅ **Карточка сотрудника** — детальная статистика за день/месяц
  - Время активности / неактивности / процент присутствия
  - Начало и конец рабочего дня
  - Детектор опозданий
- ✅ **Скриншоты** — галерея с бесконечной прокруткой (50 за загрузку), фильтры, избранное, предпросмотр
- ✅ **Мониторинг приложений** — топ используемых программ, история событий
- ✅ **USB-активность** — лог подключений флешек с содержимым
- ✅ **Браузерная история** — Chrome/Firefox/Edge по каждому сотруднику
- ✅ **Рабочие проекты** — какие файлы/проекты открывал сотрудник, сколько времени
- ✅ **Онлайн-просмотр экрана** — видеопоток в реальном времени
- ✅ **Табель** — сводная таблица по месяцу с экспортом в Excel
- ✅ **Экспорт PDF** — скриншоты сотрудника за период
- ✅ **Файловый менеджер** — просмотр и скачивание файлов с ПК сотрудника
- ✅ **Многоязычность** — Русский, Узбекский, Английский
- ✅ Роли: ADMIN и VIEWER

## 3. Как хранятся данные

### Архитектура хранилища

```
┌─────────────────────────────────────────────────────────┐
│                  Клиент (Windows)                       │
│  Шифрует данные AES-256-CBC → отправляет на сервер     │
└───────────────────────┬─────────────────────────────────┘
                        │ HTTPS POST
                        ▼
         ┌──────────────────────────────┐
         │      Бэкенд (Node.js)        │
         │   Расшифровывает → сохраняет │
         └──────┬───────────────────────┘
                │
        ┌───────┴──────────────────────┐
        ▼                              ▼
   PostgreSQL (Prisma)           Файловая система
   ──────────────────────        ─────────────────
   Структурированные данные      Медиафайлы / логи
```

### Что хранится в PostgreSQL

| Таблица | Что содержит | Срок хранения |
|---------|-------------|---------------|
| `Client` | Реестр устройств, ключи шифрования | Бессрочно |
| `Heartbeat` | Пинги от клиентов | **2 дня** |
| `Activity` | Активность/неактивность (мс) | 30 дней |
| `AppUsage` | Счётчики использования программ | 30 дней |
| `Event` | Системные события (USB, сеть, процессы) | 30 дней |
| `Screenshot` | Метаданные скриншотов (путь, время, тэги) | 30 дней |
| `BrowserActivity` | История URL с дедупликацией | ❌ Нет очистки |
| `WorkSession` | Рабочие сессии (проект, файл, фокус) | ❌ Нет очистки |
| `WorkSessionEvent` | Детальные события сессий | ❌ Нет очистки |
| `PcSession` | Загрузка/выключение ПК | ❌ Нет очистки |
| `TimesheetDay` | Агрегированный табель по дням | ❌ Нет очистки |
| `Policy` | Политики безопасности | Бессрочно |
| `AgentVersion` + `UpdateDeployment` | Обновления клиентов | ❌ Нет очистки |
| `CommandResult` | Результаты команд | **7 дней** |
| `ProjectRoot` + `ProjectAlias` | Маппинг путей к проектам | Бессрочно |
| `User` | Аккаунты администраторов | Бессрочно |

### Что хранится в файловой системе

| Папка | Содержимое | В БД | Очистка |
|-------|-----------|------|---------|
| `storage/screenshots/{clientId}/` | Файлы скриншотов (.jpg) | ✅ Запись в БД | ✅ 30 дней |
| `storage/logs/clients/{clientId}/` | Логи клиентов (текст) | ❌ Только файл | ❌ Нет |
| `storage/reports/{clientId}/` | Отчёты | ❌ Только файл | ❌ Нет |
| `storage/commands/{clientId}/` | Файлы результатов команд | ✅ JSON в БД | ✅ 7 дней |
| `storage/updates/` | Бинарники клиента | ✅ В БД | ❌ Нет |

## 4. Что не так — проблемы

### 🔴 Критические

| # | Проблема | Риск |
|---|---------|------|
| 1 | **Логи и отчёты не имеют записей в БД** — хранятся только как файлы, нельзя фильтровать/искать, нет очистки | Диск переполнится через несколько месяцев |
| 2 | **Отсутствует retention (очистка) для 6 таблиц** — WorkSession, BrowserActivity, PcSession, TimesheetDay, WorkSessionEvent, AgentVersion | БД будет расти бесконтрольно |
| 3 | **Единый ключ шифрования для всех клиентов** — нет механизма ротации ключей | Утечка одного ключа = доступ ко всем историческим данным |
| 4 | **JWT_SECRET = "devsecret" по умолчанию** — если не поменять в .env, сервер работает с дефолтным секретом | Любой может подделать токен авторизации |

### 🟡 Средние

| # | Проблема | Риск |
|---|---------|------|
| 5 | **Нет автоматического CI/CD** — сборка и деплой полностью ручные (bash-скрипты) | Человеческая ошибка при каждом релизе |
| 6 | **Минимальное покрытие тестами бэкенда** — 5 тест-файлов на ~18 000 строк кода | Регрессии не ловятся автоматически |
| 7 | **Нет health-endpoint** — нельзя мониторить сервер снаружи (Kubernetes, uptime-мониторы) | Падение сервера обнаруживается вручную |
| 8 | **Нет аудит-лога** — кто из администраторов что смотрел/скачал | Невозможно расследовать инциденты доступа к данным |
| 9 | **Листинг скриншотов — полный скан диска** — при >10 000 файлов будет тормозить или падать с OOM | Деградация при масштабировании |
| 10 | **Двойная запись команд** — результат хранится и в БД (JSON) и на диске | При сбое между двумя записями — рассинхрон |

### 🟢 Незначительные

| # | Проблема |
|---|---------|
| 11 | Нет MFA/2FA для администраторов |
| 12 | Нет версионирования API (`/api/v1/`) |
| 13 | Нет rate-limiting по endpoint (только глобальный лимит) |
| 14 | Ретроактивное применение ProjectAlias — прошлые сессии не обновляются при добавлении нового маппинга |
| 15 | Node.js 16 (требование для Windows 8) — EOL ноябрь 2026 |

## 5. На каком этапе проект

**Стадия: Бета / Пилотное использование**

Проект функционально готов для пилотного запуска на группе из 20–50 пользователей. Все ключевые функции реализованы и работают. Однако есть инфраструктурные и эксплуатационные проблемы, которые помешают стабильной работе в масштабе 200+ пользователей или в течение длительного периода (>3 месяцев) без ручного обслуживания.

```
[──────────────────────────────────────────────────────────]
 Прототип    MVP    Бета    ← МЫ ЗДЕСЬ    Релиз    Enterprise
              ↑                              ↑
        Функции                       Надёжность
        готовы                        / масштаб
```

## 7. Итоговая оценка по компонентам

| Компонент | Готовность | Комментарий |
|-----------|-----------|-------------|
| Windows-агент (клиент) | **90%** | Полнофункциональный, шифрование, очередь, обновление — всё есть |
| Бэкенд API | **75%** | Работает, но retention неполный, нет health-check, нет валидации .env |
| Веб-интерфейс | **85%** | Все страницы реализованы, UX приемлем, нет аудит-лога |
| Хранение данных | **70%** | PostgreSQL хорошо спроектирован, но есть дыры в retention и дублирование |
| Безопасность | **60%** | Шифрование есть, но дефолтные секреты, нет ротации ключей, нет аудита |
| Деплой / DevOps | **50%** | Docker Compose работает, нет CI/CD, деплой ручной |
| Тесты | **40%** | Есть базовые тесты, но покрытие минимальное |

### Общая готовность: **72%**

**Можно использовать:** пилотный запуск, демонстрация заказчику, внутреннее тестирование  
**Нельзя использовать без доработки:** production на 100+ пользователей, долгосрочная эксплуатация без DevOps-сопровождения
